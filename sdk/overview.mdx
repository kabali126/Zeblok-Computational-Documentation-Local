The Zeblok Python SDK (version 2.0.0) lets you drive the Ai-MicroCloud platform from code.
Anything you can do in the web interface — create plans, start workstations, deploy
microservices, serve AI models, run agents — you can do from a script.

## Set up

<Steps>
  <Step title="Install" icon="download">
    ```bash
    pip install "zeblok-sdk"
    ```

    That covers everything on these pages. Two features need an extra:

    | If you want | Install |
    |---|---|
    | Live status updates (`wait_until_ready`) | `pip install "zeblok-sdk[realtime]"` |
    | AWS S3 or Azure storage instead of MinIO | `pip install "zeblok-sdk[s3]"` or `[azure]` |

    Or `pip install "zeblok-sdk[all]"` for every extra at once.
  </Step>

  <Step title="Connect" icon="link">
    Everything hangs off a single client. Create it once, then reach each component from it.

    ```python
    import os

    from zeblok import ZeblokClient

    client = ZeblokClient(
        os.environ["ZBL_APP_URL"],        # e.g. "https://app.your-env.zeblok.com"
        os.environ["ZBL_ACCESS_KEY"],
        os.environ["ZBL_ACCESS_SECRET"],
    )
    ```

    <Tip>
      Paste whatever URL you use in the browser. The web app and the REST API are served from
      different hosts, and which prefix is correct differs per environment — the client checks
      and switches for you.
    </Tip>
  </Step>

  <Step title="Check it works" icon="circle-check">
    ```python
    print(client.health())    # {'status': 'ok', ...}  -> platform reachable
    print(client.config())    # {'tier': 'pro', ...}   -> your key works
    ```

    Both printing means you are connected and authenticated. If not, see
    [Authentication](/sdk/authentication).
  </Step>
</Steps>

## How every page here is organised

Each component page follows the same shape, so once you learn one you know them all:

| Part | What it gives you |
|---|---|
| **Capabilities** | A table of every operation, the SDK call, and the REST endpoint behind it |
| **Examples** | Ready-to-copy code for the common paths |
| **Notes** | The behaviour worth knowing before you hit it |

<Warning>
  **Two kinds of call.** Reads (`get_all`, `get_by_id`, `list`, `validate_id`) only look —
  run them freely. Writes (`create`, `update`, `delete`, `spawn`, `stop`) change real things
  and consume real resources.
</Warning>
