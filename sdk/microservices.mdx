---
title: "Microservices"
description: "Deploy an application and keep it running."
---

Same two halves as workstations — a **catalog** of application images, and the **running**
services deployed from them.

## Capabilities

### Catalog

| What you want to do | SDK call | API |
|---|---|---|
| Browse the catalog | `client.microservices.get_all()` | `GET /api/v1/microservices` |
| Get one template | `client.microservices.get_by_id(id)` | `GET /api/v1/microservices/:id` |
| Public marketplace | `client.microservices.get_all_public()` | `GET /api/v1/microservices/public` |
| Add a template | `client.microservices.create(...)` | `POST /api/v1/microservices` |
| Update a template | `client.microservices.update(id, ...)` | `PUT /api/v1/microservices/:id` |
| Remove a template | `client.microservices.delete(id)` | `DELETE /api/v1/microservices/:id` |

### Running services

| What you want to do | SDK call | API |
|---|---|---|
| Deploy one | `client.microservices.spawn(...)` | `POST /api/v1/spawned-services` |
| List running | `client.microservices.spawned()` | `GET /api/v1/spawned-services` |
| Pod name → id | `client.microservices.get_spawned_id_by_name(pod)` | `GET /api/v1/spawned-services` |
| Replica counts | `handle.replica_status()` | `GET /api/v1/spawned-services/replica-status/:id` |
| Everything after that | See [Workload lifecycle](/sdk/lifecycle) | — |

## Read the template's defaults

```python
catalog = client.microservices.get_all(print_stdout=False)

MICROSERVICE_ID = catalog[0]["id"]
ms = client.microservices.get_by_id(MICROSERVICE_ID, print_stdout=False)

print("image tags:", ms["display_names"])
print("defaults  :", ms.get("parameters"))     # ports / envs / args / volumePath
```

<Tip>
  Those `parameters` are what the web interface pre-fills into its deploy form. The SDK
  inherits them when you omit `ports` and `envs` — pass your own, or `[]`, to override.
</Tip>

## Deploy

```python
pod_name, url = client.microservices.spawn(
    display_name=ms["display_names"][0],
    microservice_id=MICROSERVICE_ID,
    plan_id=PLAN_ID,
    microservice_name="orders-api",       # unique, lowercase
    namespace_id=NAMESPACE_ID,

    # ports=[{"protocol": "HTTP", "portIdentifier": "http", "number": 8080}],
    # envs=[{"key": "LOG_LEVEL", "value": "debug"}],
)

svc_id = client.microservices.get_spawned_id_by_name(pod_name)
handle = client.spawned("service", svc_id)

print("open at:", handle.open_url())
print("call it from inside the cluster at:", handle.internal_url())
print("replicas:", handle.replica_status())
```

<Note>
  Use the **internal** address for service-to-service calls — it stays inside the cluster,
  which is faster and does not depend on the public route.
</Note>

## Add your own application to the catalog

```python
entry = client.microservices.create(
    "my-api",
    "Our internal orders API",
    [{"displayName": "my-api:1.0", "dockerImage": "myorg/my-api:1.0"}],
    "open source",

    visibility="private",
    parameters={
        "ports": [{"protocol": "HTTP", "portIdentifier": "http", "number": 8080}],
        "envs":  [{"key": "LOG_LEVEL", "value": "info"}],
    },
)
```

<Tip>
  Setting `parameters` here saves everyone time later — whoever deploys the template gets
  your ports and environment variables without having to know them.
</Tip>
